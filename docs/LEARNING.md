# Разработка с обучением

Этот проект — пет для прокачки, не гонка «чтобы ИИ всё написал».  
Цель: понимать каждую строку, которую коммитишь.

Связано с порядком фич: [`PLAN-MODULES.md`](./PLAN-MODULES.md).

---

## Как работать с ИИ (метод 4+1 шагов)

### 1. Сначала логика своими словами
Перед редактором или промптом — алгоритм в 3–4 шагах (бумага / комментарий / чат).

Пример: «1. Принять account_id → 2. Проверить в БД → 3. Если нет — OpenDota → 4. Сохранить матчи».

### 2. Проси «выжатый контекст», не готовый модуль
Вместо «напиши весь файл» или трёх часов вики — три вещи:

1. **Концепция** — механизм в 2–3 предложениях  
2. **Минимальный паттерн** — скелет синтаксиса на 5–10 строк (без твоей бизнес-логики)  
3. **Ключевые термины** — 2–3 символа/функции из библиотеки, которые применить  

Пример промпта:  
«Я делаю settings через env. Как pydantic-settings BaseSettings читает `.env`? Концепция + 5–10 строк паттерна + какие классы/поля важны. Код файла целиком не пиши.»

### 3. Код пишешь только руками
Даже мини-паттерн из ответа — перепечатай под свои имена файлов/полей. Без Ctrl+C / Ctrl+V готовых кусков в репо.

### 4. Правило «15 минут на баг»
1. 10–15 минут: Traceback, место падения, своя попытка починить  
2. Если застрял — код + ошибка с промптом:  
   «Где я ошибся? Не давай исправленный файл — укажи строку и объясни причину.»

### 5. Code review после «уже работает»
«Этот код работает. Я учусь: найди 2 узких места и объясни, как правильнее.»

## Дополнения под этот репо

- Иди по модулям из `PLAN-MODULES.md`. Не тяни ML/LLM, пока нет health → DB → ingest.  
- Перед кодом зафиксируй **DoD** одной фразой (например: `curl /health` → 200 и имя из `.env`).  
- Официальные доки — точечно по задаче; ИИ указывает «какой раздел», не заменяет чтение.  
- После модуля — 3–5 строк в `docs/notes.md` (что узнал / где застрял). Файл заведи, когда появится первая заметка.

## Контракт с ассистентом в Cursor

| Ты пишешь | Ассистент делает |
|-----------|------------------|
| (по умолчанию) | инструкции, концепт, мини-паттерн, термины — **без правки репо и без полных файлов** |
| «сделай сам» / «напиши файл» | можно править код в проекте |
| traceback + код + «не патчи» | указать место ошибки и почему |
| «code review» | замечания по работающему модулю |

Не нужно каждый раз пересказывать методологию, если открыт этот проект: правило в `.cursor/rules/` подхватывает этот документ.  
В **новом чате вне репо** или без правил — коротко напомни: «по docs/LEARNING.md».
