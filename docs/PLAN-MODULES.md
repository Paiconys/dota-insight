# Dota Insight Hub — план по модулям

Пет-проект: full-stack (уклон backend + data), mid-level.  
Цель: статистика матчей Dota 2 → дашборд → AI-разбор → модели.  
Стек-ориентир: **FastAPI + Postgres + Redis + Next.js + (позже) ML/LLM**.

Как пользоваться этим файлом: иди **строго по фазам**. Следующий модуль не начинай, пока у текущего нет галочки DoD.

Как учиться и как просить ИИ: [`LEARNING.md`](./LEARNING.md) (правило Cursor подхватывает автоматически).

## Модуль 1 — Domain & DB

**Цель:** модель данных под игрока и матчи.

**Сделать:**
- [ ] таблицы (минимум):
  - `players` — steam_id / account_id, display_name, created_at

  - `player_matches` — account_id, match_id, hero_id, kills/deaths/assists, side, rank?, raw jsonb
  - `sync_cursors` — account_id, last_fetched_at, last_match_id
- [ ] Alembic migration #1
- [ ] SQLAlchemy/SQLModel модели + репозитории (тонкий слой)

**DoD:** миграция применяется на чистой БД без ошибок; можно вставить тестовый матч руками.

**Не делать:** вызовы внешних API.

## Модуль 2 — OpenDota Ingest

**Цель:** по `account_id` забрать список матчей и детали, сохранить в БД.

**Сделать:**
- [ ] HTTP-клиент OpenDota (таймауты, retry, уважение rate limit)
- [ ] сервис `fetch_player_matches(account_id, limit)`
- [ ] сервис `fetch_match(match_id)` + upsert в `matches` / `player_matches`
- [ ] CLI или временный endpoint `POST /dev/sync/{account_id}` (потом убрать/закрыть)

**DoD:** один реальный account_id → в БД ≥ N матчей с героями и KDA.

**Не делать:** красивый UI, фоновые воркеры (это модуль 5).

**Риск:** лимиты API — сразу логировать 429 и backoff.

## Модуль 3 — Core API

**Цель:** стабильный REST, которым будет пользоваться фронт.

**Endpoints (MVP):**
- [ ] `GET /players/{account_id}` — профиль / сводка
- [ ] `GET /players/{account_id}/matches?limit=&offset=` — список
- [ ] `GET /matches/{match_id}` — детали матча (+ участник, если есть)
- [ ] `POST /players/{account_id}/sync` — триггер синка (пока синхронно или stub → очередь)

**Сделать:**
- [ ] Pydantic-схемы ответов
- [ ] пагинация, понятные ошибки 404/422
- [ ] CORS под localhost фронта

**DoD:** через httpie/curl видно список матчей из БД без лезть в SQL.

## Модуль 4 — Web Dashboard (MVP UI)

**Цель:** открыл сайт → ввёл Steam/account id → увидел матчи.

**Страницы:**
- [ ] Home: ввод account_id + кнопка Sync / Load
- [ ] Player: таблица матчей (герой, результат, KDA, длительность, дата)
- [ ] Match: карточка одного матча

**Стек UI:** Next.js (App Router) + простой CSS/Tailwind без оверинжиниринга.

**DoD:** end-to-end: sync → список → клик в матч. Это первый «вау» для портфолио и для себя.

**Не делать:** графики winrate, AI-текст, авторизацию Steam (можно позже).

## Модуль 5 — Jobs & Sync

**Цель:** долгий sync не блокирует API.

**Сделать:**
- [ ] Redis + worker (Celery / ARQ / RQ — выбрать один)
- [ ] задача `sync_player_matches`
- [ ] статус джобы: `queued | running | done | failed` (таблица или Redis)
- [ ] API: `POST .../sync` → job_id; `GET /jobs/{id}`

**DoD:** sync 100+ матчей из UI без таймаута HTTP; можно обновить страницу и увидеть прогресс/готово.

## Модуль 6 — Analytics Aggregates

**Цель:** цифры, ради которых заходишь после катки.

**Фичи:**
- [ ] winrate общий / за период
- [ ] winrate по героям (топ / худшие)
- [ ] средний KDA, длительность, роли (если есть в данных)
- [ ] простая серия: последние 20 матчей (W/L sparkline)

**Реализация:**
- сначала SQL-агрегации по `player_matches`
- при тормозах — материализованные таблицы / nightly job

**API:**
- [ ] `GET /players/{account_id}/stats`
- [ ] `GET /players/{account_id}/heroes`

**UI:** блок статистики на странице игрока + 1–2 графика.

**DoD:** после sync страница игрока показывает осмысленные агрегаты без ручного Excel.

## Модуль 7 — AI Coach (LLM)

**Цель:** «полезное после катки» — текстовый разбор.

**Сделать:**
- [ ] промпт: вход = структурированные статы матча + сравнение со средним игрока
- [ ] `POST /matches/{id}/coach` → `{ summary, strengths[], improvements[] }`
- [ ] кэш ответа в БД (`match_insights`), чтобы не жрать токены повторно
- [ ] UI: кнопка «AI разбор» на странице матча

**DoD:** на реальном матче текст конкретный (герои, цифры), не вода.

**Не делать:** fine-tune своих весов — пока API LLM (OpenAI/совместимый).

## Модуль 8 — ML Signals

**Цель:** своя модель на фичах матчей (портфолио «data/ML»).

**Сделать:**
- [ ] notebook или `ml/` пакет: выгрузка датасета из Postgres
- [ ] фичи v1: hero_id, side, duration bucket, KDA proxy, rank (если есть)
- [ ] baseline: логистическая регрессия / XGBoost → P(win) для строки игрока
- [ ] артефакт модели + `POST /ml/predict-match` или скоринг при ingest
- [ ] метрики: AUC/accuracy на holdout + честное «это toy, не беттинг»

**DoD:** модель обучается из твоих (или публичных) матчей; API отдаёт score; в UI бейдж «model confidence».

**Зависимость:** достаточно данных в БД (модули 2+5), иначе сначала массовый backfill.
